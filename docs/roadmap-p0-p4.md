# P0–P4 交付路线与完成证据

本文把现有后端、前端和运行验收文档统一成一个可审计路线。P0–P3 沿用
既有定义；原文没有 P4，因此 P4 明确定义为生产化与发布验收，而不是新增
未经验证的产品功能。

截至 2026-07-30：后端和前端 P0–P3 契约主链已实现；本路线中的真实供应商、真实对象存储、托管环境和浏览器 E2E 仍是验收门槛。前端详细状态见[前端实现状态](./frontend/implementation-status.md)。

## P0：数据内核

范围：

- 安全链接导入、账号扫描、详情 Hydration。
- Provider Adapter、原始响应、标准化、去重和指标快照。
- PostgreSQL 持久任务、缓存、预算、成本和基础灵感查询。
- 前端工作台、对标账号、任务与最小灵感入口。

完成证据：

- 至少三个平台各导入 5 条真实公开内容。
- 10 个账号完成增量扫描，Cursor 失败不前移。
- 重复导入、缓存、429/5xx、认证失败、预算和工作区隔离通过测试。
- 真实 PostgreSQL、Worker 和 TikHub 小规模 Smoke Test 通过。

## P1：判断与分析

范围：

- 版本化评分策略、首次证据冻结、L1、转写和 L2。
- 评论样本、搜索发现、灵感库、可复用模式和费用看板。
- 前端灵感详情、分析、发现、模式与用量页面。

完成证据：

- 评分只使用候选内容发布前的数据，样本不足不强行评级。
- AI 输出通过 JSON Schema，保存模型、Prompt、输入 Hash、费用和来源引用。
- L2 只处理策略允许内容；模型或 Prompt 更新不覆盖历史。

## P2：生产工作流

范围：

- 自有账号、选题、内容项目、脚本版本、素材、审核与排期。
- 人工发布包、发布记录、24h/7d/30d 复盘。
- 对应前端生产、日历、发布和复盘页面。

完成证据：

- 状态机、乐观锁和脚本追加版本通过并发测试。
- 从灵感到选题、脚本、发布包、发布记录和复盘的 E2E 通过。
- 素材直传、MIME、大小、Hash、权限和权利说明验证通过。

## P3：增强能力

范围：

- 已进入当前契约：保存视图、统一关键词搜索、团队权限、版本化运营实验和转化归因。
- 后续外部能力：官方发布 Provider、向量语义搜索、独立通知投递和多供应商容灾。
- 可选体验增强：暗色模式、更多实体批量操作和容量/成本优化。

完成证据：

- 统一关键词搜索、保存视图和实验结果有可解释来源、版本和审计记录。
- 官方接口权限、认证和人工审核边界通过供应商验收后，才把官方发布标记为完成。
- Provider 故障切换不重复产生发布或付费副作用。
- 搜索与实验结果有可解释来源、版本和审计记录。

## P4：生产化与发布验收

范围：

- 托管 PostgreSQL、对象存储、Secret Store、备份/PITR 和恢复演练。
- API、Worker、Scheduler 部署，日志、指标、告警、熔断与预算硬保护。
- OpenAPI 兼容检查、容器、CI/CD、Staging Smoke、性能与安全验收。
- 数据保留、删除、版权/隐私流程和运营手册。

完成证据：

- P0–P3 所有验收项有当前环境的可复现证据。
- 生产备份恢复、Worker 崩溃恢复、供应商故障和预算 100% 演练通过。
- 核心查询达到 P95 500ms 目标；Secret 扫描和依赖安全检查通过。
- 发布 Runbook、回滚方案、责任人和首批真实工作区验收签字齐全。
